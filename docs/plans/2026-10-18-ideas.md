# Ideas: non-blocking agents, approval flow, efficiency

Source: three research agents (blocking, approval flow, efficiency). Facts cite code in their reports; ideas below are proposals.

## Findings that shape everything
- `request_decision` holds one HTTP request open until a Verdict (`mcp.ts:65`, `decisions/main/index.ts:139-145`). 24h tool timeout (`claude-code/index.ts:47`). No async mode.
- Waiters live in memory only. Run stop, agent disconnect or app restart leaves the Decision pending and the Verdict reaches only a later Run, via the static pointer "Past Decisions are in .decisions/" (`runs/main/index.ts:8`). Nothing marks which Verdicts an agent has seen.
- `waiting` entry is never removed on Run stop (`mcp.ts:93`).
- Out-of-Scope already returns the recommendation at once and lands in Review (`index.ts:121-134`): the non-blocking path exists in miniature.

## Non-blocking (core question)
| # | Idea | Value | Cost | Risk |
|---|------|-------|------|------|
| N1 | Park-and-continue: `blocking: "soft"` returns at once "Parked D12, proceeding on option 2", agent continues on the recommendation | very high | medium | rework if overturned |
| N2 | `check_decisions` tool: returns Verdicts of this Run's parked Decisions since last call; per-Run delivered marker | very high (closes N1) | small | agents may not poll |
| N3 | Unseen-Verdicts startup line replaces the static pointer; same delivered marker | high | small | double-applied Verdicts |
| N4 | `inform` tool: log "did X because Y" straight to Review, no wait | high | small | agents dodge asking; cap it |
| N5 | Batch `request_decisions([...])` | medium | high | still blocks until all answered |
| N6 | Persist timeout progress, default timeout | medium | small | contradicts UC5.3 "closed app leaves pending" |
| N7 | Orphan cleanup: drop waiter on Run stop/close, mark card "orphaned" | hygiene | small | low |

N1 and N2 ship together: soft ask without a way back is a dead end. N7 is the prerequisite.

## Approval flow
| # | Idea | Value | Cost | Risk |
|---|------|-------|------|------|
| A1 | Feed order by unblock value (nearest timeout, blocked agents, age); fix `first` vs newest-first mismatch (`Feed.tsx:250`) | high | small | low |
| A2 | Snooze (icon + key): card to bottom, timeout paused | medium | small | agent stays blocked longer |
| A3 | Bulk Accept in Review (one icon) | medium | tiny | low |
| A4 | Cross-Project jump to next Project with pending | medium | small | low |
| A5 | Precedent: mark/auto-resolve when same question in same Scope was accepted before | high over time | medium | stale precedent |
| A6 | Batch similar pending Decisions into one Verdict | medium | high | approving unseen |
| A7 | OS notification (opt-in) | latency only | small | UC4.6 defers it |

Soft Decisions (N1) are lower-stakes by definition; they could sort below hard ones (A1).

## Efficiency
| # | Idea | Value | Cost |
|---|------|-------|------|
| E1 | Compact tool schema: cap/omit inline Component ids (`mcp.ts:23`), shorten `mockup` description (`mcp.ts:30`) | tokens on every Run | ~10 lines |
| E2 | Single `decisions:changed` consumer (3-4x reads per change today) | I/O | small |
| E3 | Path-filter Project watcher (node_modules, out/); avoid groma re-walk | multi-Project load | ~5 lines |
| E4 | Cache `componentIds` per MCP request / only on `tools/list` | latency | ~15 lines |
| E5 | Async `loginPath` (up to 3s main-thread block on first Run) | startup | ~10 lines |
| E6 | Test speed: explicit workers, skip rebuild when `out/` is fresh | dev loop | config |
| E7 | History prune/archive, readAll cache | only at large history | defer |

## Ruled out
SQLite/queue (ADR 0003), persistent MCP sessions with push (clients ignore it), MCP elicitation, true Run resume (ADR 0007), default Approve button, answer templates, decision dependencies, sounds.

## Recommendation
Do N7, N1+N2, N3, N4 (the non-blocking spine), then A1, A2, A3, then E1-E3, E5. Defer N5, N6, A4-A7, E4, E6, E7.
