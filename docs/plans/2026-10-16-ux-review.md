# UX review (TASK-32)

Status: done 2026-10-16. Walked by code inspection (two read-only reviews, UC1-UC8 + UC10); every Q fix below shipped with a scenario (150 scenarios pass), larger ones are Backlog tasks below; all of TASK-34..44 are done. Interview done 2026-10-17, decisions: TASK-36 modifier keys everywhere (⌘N/⌘S/⌘X, tooltips follow); TASK-37 hover focus pauses ~1 s after any keystroke; TASK-43 check the plugin before the setup Run and explain a missing one, "Open existing folder" becomes the primary card; TASK-44 map tabs and Up get tooltips with shortcuts, UC7.3 stays and Project tabs jump with ⌘⇧1..9.

Deviations while shipping: U8 invalid timeout keeps the stored value (not cleared); U16 dialog title/button has no scenario (no fake OS dialog in tests); U5 `,` no longer closes Settings (Esc and the Close icon do); U18 star tooltip is an SVG `<title>`, hidden under the option tooltip while the star ignores the pointer.

Goal: find out whether a first-time user can do what `docs/use-cases.md` promises without reading it, and fix what gets in the way. Looks at usability (can they), not visuals (TASK-10 covered those).

## Method
- Walk UC1-UC8 and UC10 end to end in the built app (`npm run dev`, real Claude Code where possible, the fake adapter otherwise), as a user who has never seen the mock.
- Per step note: what the user looks for, what they find, how many actions, what feedback they get, what they do when it fails. Score each finding Blocker / Major / Minor.
- Check the cross-cutting rules too: every icon has a tooltip with its shortcut and the shortcut works; focus ring shows where keys act; empty states explain the next action; errors say what to do; keys never fire inside a text field.
- Then interview the user with the findings (AskUserQuestion) before fixing anything bigger than a one-liner.

## Walkthroughs (what to look for)
1. First launch: empty window to first Run. Is "set up a new project" vs "open a folder" clear? Does the grill interview start where the user expects? What if `claude` is missing (UC3.5)?
2. Start a Run and give it a task: do users find the start icon, understand the Run name, know they must type the task in the terminal? Is "waiting" (amber dot, chip, notification) noticed?
3. Take a Decision from the Feed: card reads in one glance? L / 1-4 / D / C discoverable without tooltips? Does the card leaving and focus moving feel right? "Show in Run (J)" understood?
4. Scopes: do users understand In-Scope / Out-of-Scope from the modal alone? Timeout field clear? Consequence (Review tab) visible?
5. Review and History: is the difference obvious? Is Overturn's comment box understood? Superseded rows readable?
6. Panes and focus: hover focus (150 ms) surprising or helpful? Pane hide/show and ⌘1/2/3 found? Terminal keys (⌘F, ⌘J, Shift+Enter) found?
7. Files: lock banner and "Edit anyway" understood? Save feedback enough?
8. Decision map: empty state leads to a Run? Overview vs Interactions grasped? Hover lists readable?
9. Many Runs and Projects: does the sidebar still scan? Badges clear?

## Deliverables

- Quick fixes (wording, tooltip, empty state, one guard) shipped in this task, each with a scenario.
- Anything larger: one Backlog task per fix, ordered by severity and dependency (`--ordinal`, `--dep`), listed below.
